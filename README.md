## 📌 Overview

This repository contains the complete source for **[md-mahfujur-rahman.vercel.app](https://md-mahfujur-rahman.vercel.app)** — a portfolio built for an AI/ML engineer and researcher. It is more than a static page: every section (profile, projects, publications, skills, achievements, blog, contact messages) is **database-driven**, managed through a REST API, and served by a FastAPI backend backed by PostgreSQL.

The site is styled as a "Deep Space" AI theme — a dark (`#050814`) glassmorphic UI with neon cyan (`#00f2fe`) and purple (`#8b5cf6`) accents, animated gradient orbs, data-stream particle effects, and typewriter headlines. The data model is tailored to research work: projects carry *datasets, models, metrics, architecture and deployment* fields, while publications carry *venue, DOI, methodology, experiments and key results*.

## ✨ Highlights

### Frontend
- **Route-level code splitting** — every page is a lazily-loaded chunk (`React.lazy` + `Suspense`), so visitors only download what they navigate to.
- **Smart data layer** — TanStack Query v5 with a 5-minute `staleTime` (matching the backend's `Cache-Control`), automatic de-duplication, and shared hooks (`useProfile`, `usePublications`) so Hero/About/Contact never fetch the profile twice. A promise-level dedupe at the service boundary guarantees a single profile request even before the cache warms up.
- **Lightweight payloads** — list endpoints return slim schemas (heavy JSONB detail fields are excluded until the detail page needs them); a dedicated `/publications/{slug}/neighbors` endpoint replaced the old "fetch 200 rows to render prev/next" pattern.
- **Production build tuning** — Brotli pre-compression (`.br` assets Vercel can serve directly), manual `vendor` chunking, `es2020` target, CSS code-splitting, and a bundle visualizer (`dist/stats.html`).
- **Rich UI kit** — 46 prebuilt shadcn/ui components (Radix primitives), Motion (Framer Motion successor) animations, lucide icons, sonner toasts, Recharts, Embla carousels, canvas-confetti, and `DOMPurify`-sanitized blog HTML.
- **Interactive contact form** with success confetti, plus blog comments & threaded replies.

### Backend
- **Security-first mutations** — all `POST/PUT/DELETE` routes are gated by an `X-Admin-Token` header compared with `secrets.compare_digest` (constant time) and **fail closed** (HTTP 503) if no token is configured. Public `GET` routes stay open.
- **Rate limiting** (slowapi) to protect free-tier compute: `10/min` for comments & replies, `5/min` for contact submissions.
- **HTTP caching** — `Cache-Control: public, max-age=300, stale-while-revalidate=60` on lists, `max-age=600, swr=120` on detail routes; GZip compression for responses ≥ 500 bytes.
- **N+1-free queries** — skills are eager-loaded with `selectinload`; the stats endpoint returns aggregate `COUNT`s instead of shipping rows.
- **Self-provisioning schema** — tables are created automatically on startup (`Base.metadata.create_all`), so the API boots against an empty database.
- **Postgres-native modeling** — `JSONB` for flexible detail fields, `ARRAY(Text)` for tags/tech stacks, `UUID` primary keys for profile & messages, and a GIN index on `projects.tech_stack` for tech-stack filtering.

## 🏗️ Architecture

```
┌─────────────────────────────┐        ┌──────────────────────────────┐        ┌──────────────┐
│   Frontend (Vercel)         │  JSON  │   API (Render)               │  SQL   │  PostgreSQL  │
│   React 18 + Vite 6 + TS    │───────▶│   FastAPI + SQLAlchemy       │───────▶│              │
│   Tailwind 4 + shadcn/ui    │  CORS  │   slowapi · GZip · CORS      │        │  11 tables   │
│   TanStack Query cache      │        │   X-Admin-Token auth         │        │              │
└─────────────────────────────┘        └──────────────────────────────┘        └──────────────┘
        ▲                                          ▲
        │ VITE_API_BASE_URL baked in at build      │ Swagger UI auto-served at /docs
        └──────────────────────────────────────────┘
```

- The frontend talks to the API via `VITE_API_BASE_URL` (embedded at build time; defaults to same-origin `""` in dev).
- The API serializes **camelCase JSON** (Pydantic `alias_generator`) while storing snake_case columns — both shapes are accepted on input.
- Content is managed entirely through the API (see [Content Management](#🔐-content-management-admin-only)).

## 🗄️ Data Model

11 PostgreSQL tables (auto-created on startup):

| Table | Purpose | Notable fields |
|---|---|---|
| `profile` | Owner identity (single row) | `social_links JSONB`, `resume_url`, `UUID` PK |
| `projects` | Case-study projects | `tech_stack ARRAY` (GIN-indexed), `dataset/model/metrics/deployment JSONB`, unique `slug` |
| `publications` | Research papers | `venue`, `year`, `doi_url`, `key_results ARRAY`, `experiments JSONB`, unique `slug` |
| `blogs` | Articles | `content`, `tags ARRAY`, `published_date` |
| `blog_comments` | Threaded comments | self-referencing `parent_id`, cascade deletes |
| `skill_categories` / `skills` | Skills grouped by category | `level` per skill, `SET NULL` on category delete |
| `achievements` | Awards & certifications | `organization`, `year`, `certificate_url` |
| `contact_messages` | Inbox | `UUID` PK, indexed `email`, `status` |
| `contact_comments` | Public guestbook entries | `avatar` |
| `api_request_logs` | Request audit log (model defined, not yet wired to middleware) | method, path, status, ip, bodies |

## 🚀 Getting Started

### Prerequisites
- **Python 3.10+** and **Node.js 18+** (20 LTS recommended)
- A **PostgreSQL** database (local or hosted, e.g. Neon/Render/Supabase)

### 1. Backend

```bash
cd Backend

# Create & activate a virtual environment
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt

# Configure environment
cp .env.example .env
#   DATABASE_URL=postgresql://user:password@host:5432/dbname
#   ADMIN_TOKEN=$(python -c "import secrets; print(secrets.token_urlsafe(32))")
#   ALLOWED_ORIGINS=http://localhost:5173

# Run (must be started from the Backend/ directory — imports are rooted there)
uvicorn app.main:app --reload --port 8000
```

Tables are created automatically on first boot. Swagger UI is available at `http://localhost:8000/docs`.

### 2. Frontend

```bash
cd Frontent

npm install                      # or: pnpm install

# Point the SPA at your local API
echo "VITE_API_BASE_URL=http://localhost:8000" > .env.local

npm run dev                      # → http://localhost:5173
```

### 3. Production build

```bash
cd Frontent
npm run build                    # → dist/ with Brotli (.br) assets + dist/stats.html bundle report
```

## 🔐 Content Management (Admin only)

There is no admin UI — content is managed via the API using the `X-Admin-Token` header:

```bash
export API=https://mahfuj-portfolio.onrender.com
export ADMIN_TOKEN="<your-token>"

# Upsert the profile
curl -X PUT $API/api/v1/profile \
  -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Md. Mahfujur Rahman","tagline":"AI Engineer","socialLinks":[{"platform":"github","url":"https://github.com/mahfujr403"}]}'

# Create a project
curl -X POST $API/api/v1/projects \
  -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"slug":"my-project","title":"My Project","summary":"…","techStack":["Python","FastAPI"]}'

# Create a skill category + skill
curl -X POST $API/api/v1/skills/categories -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H "Content-Type: application/json" -d '{"name":"Machine Learning"}'
curl -X POST $API/api/v1/skills -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H "Content-Type: application/json" -d '{"categoryId":1,"name":"PyTorch","level":90}'
```

Both `camelCase` and `snake_case` keys are accepted on input (Pydantic `populate_by_name`).

## 🛡️ Security Model

- **Admin gate** — every mutating route depends on `require_admin()`: missing server token → `503` (fail-closed, never silently permissive); wrong/missing client token → `401`. Comparison uses `secrets.compare_digest` to resist timing attacks.
- **Rate limiting** — public write endpoints (comments, replies, contact) are throttled per client IP via slowapi.
- **CORS** — explicit origin allowlist from `ALLOWED_ORIGINS`; credentials disabled.
- **XSS hygiene** — blog HTML is sanitized with `DOMPurify` before rendering; email fields validated with `EmailStr`.
- **Secrets** — no secrets in the repo (`.env` gitignored at both root and app level; only `.env.example` is committed).

## ⚡ Performance Notes

- **Edge-to-DB caching alignment** — React Query `staleTime` (5 min) mirrors backend `Cache-Control: max-age=300`, so CDN, browser, and client caches expire together.
- **Request de-duplication** at three levels: React Query key dedupe, shared `useProfile`/`usePublications` hooks, and a promise-level guard in `profileApi.ts`.
- **Payload slimming** — list responses strip heavy JSONB fields; `/stats` returns counts only; `/publications/{slug}/neighbors` replaces 200-row fetches with a slug+title pair.
- **Query efficiency** — `selectinload` eliminates the skills N+1; `limit` is bounded server-side on every list route (caps of 50–1000 depending on endpoint, `ge=1` on projects/publications/blogs).
- **Bundle** — route-level lazy chunks, vendor split, ES2020 target, Brotli pre-compression; inspect with `dist/stats.html` after building.
- **CORS-friendly fetches** — the API client omits `Content-Type` on bodyless GETs to avoid needless preflights.

## 🧭 Development Notes & Known Issues

Honest findings from a full code review — good first contributions:

- 📁 The frontend folder is named **`Frontent`** (typo for "Frontend"). Renaming requires updating the Vercel root-directory setting in the same change.
- 💬 `blogApi.ts` carries a stale comment claiming the app uses local mock data — it actually calls the live API (the referenced `src/data/blogs.ts` doesn't exist). The comment can be deleted.
- 📮 `ContactMessageCreate` accepts a `subject` field, but `POST /api/v1/contact` never persists it (only `name`, `email`, `message` are saved).
- 📝 The `APIRequestLog` model exists but no middleware writes to it yet.
- 🤖 `POST /api/v1/predict` is an intentional placeholder for future ML model serving.
- 🧪 No automated tests, linting, or CI yet (`package.json` only defines `dev` and `build`).
- 📜 No `LICENSE` file — consider adding one (e.g. MIT) if you want to make the code reusable.
- ⚛️ `react`/`react-dom` are declared as optional `peerDependencies` (a Figma Make artifact); npm/pnpm auto-install them, but moving them to `dependencies` would be more conventional for an app.
